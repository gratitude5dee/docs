title: "Quickstart"
description: "Install the Zap v5 CLI, check your setup with doctor, and compose your first runtime — all plan-only and zero-spend."
---

Zap requires Node 24.x. Every command supports `--json`: humans get text, agents get JSON.

<Steps>
  <Step title="Check your setup">
    ```bash
    npx @wzrdtech/zap@5.0.1 doctor --json
    ```

    `doctor` reports Node version, payer mode (`byok` | `managed` | `missing`), sandbox availability, and template status.
  </Step>
  <Step title="Compose a runtime">
    ```bash
    npx @wzrdtech/zap@5.0.1 init
    npx @wzrdtech/zap@5.0.1 compose --weight med --sandbox box --dry-run --json
    ```

    `compose` resolves `Runtime.md` (or `zap.config.ts`) into a deterministic plugin tree without acquiring anything. Equivalent `Runtime.md` and `zap.config.ts` definitions produce identical trees and lock hashes. Drop `--dry-run` to boot the runtime on your sandbox.
  </Step>
  <Step title="Manage the runtime">
    ```bash
    zap runtime up --json
    zap runtime ps --json
    zap runtime exec <id> -- echo hello
    zap runtime down <id>
    ```

    `zap runtime` also supports `logs`, `snapshot`, `fork`, `stop`, `resume`, and `desktop`. `zap fs <ls|read|write|rm> <runtime-id> <path>` operates on the runtime's filesystem.
  </Step>
  <Step title="Stay plan-only, or go live">
    Plan-only is the default everywhere. Side-effecting work emits `tool.planned` events with cost estimates. To spend for real:

    ```bash
    zap pay status                 # payer: byok | managed | missing
    zap keys add openrouter        # BYOK, or:
    zap pay login --managed        # spend-capped managed wallet
    zap run <Zap.md> --live        # now spends
    ```

    <Warning>No payer + `--live` fails closed with `PAYER_MISSING` — never a silent downgrade.</Warning>
  </Step>
</Steps>

## Install options

```bash
npm install --global @wzrdtech/zap   # zap on your PATH
zap --version
```

Or project-local: `npm install --save-dev @wzrdtech/zap`, then `npm exec -- zap --version`.
